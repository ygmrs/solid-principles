# SOLID Principles

Java examples demonstrating the SOLID object-oriented design principles and their role in creating maintainable, extensible, and loosely coupled software.

## Overview

SOLID is a set of five software design principles used to improve object-oriented structure, reduce unnecessary coupling, and make systems easier to extend and maintain.

This repository contains Java examples focused on the five principles:

- **S — Single Responsibility Principle**
- **O — Open/Closed Principle**
- **L — Liskov Substitution Principle**
- **I — Interface Segregation Principle**
- **D — Dependency Inversion Principle**

## Principles

### Single Responsibility Principle

A class should have one primary responsibility and one reason to change.

### Open/Closed Principle

Software components should be open for extension while remaining closed for unnecessary modification.

### Liskov Substitution Principle

Subtypes should be usable in place of their base types without changing the expected behavior of the system.

### Interface Segregation Principle

Clients should depend only on the operations they actually require rather than large, general-purpose interfaces.

### Dependency Inversion Principle

High-level components should depend on abstractions rather than concrete implementation details.
